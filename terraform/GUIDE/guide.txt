# What I would change

## 1. Move MySQL to RDS

Don't autoscale MySQL EC2.

Instead:

```text
EC2 MySQL  ❌
RDS MySQL  ✅
```

Benefits:

* Automated backups
* Multi-AZ
* Automatic patching
* Easier maintenance
* Production-grade architecture

For interviews and resumes this is also much stronger.

---

## 2. Frontend should NOT be on EC2

You currently have:

```text
Frontend EC2
Backend EC2
MySQL EC2
```

I would move frontend to:

```text
S3 Static Website
+
CloudFront
```

Architecture:

```text
Users
  |
CloudFront
  |
S3 Frontend
```

Benefits:

* Cheaper
* Faster
* Highly available
* No autoscaling required

Your React/Vue/HTML frontend becomes static assets.

---

## 3. Backend in ASG

Keep backend on EC2.

```text
Private Subnet
    |
ASG
    |
Launch Template
```

Min: 2

Desired: 2

Max: 4

Across two AZs.

---

# Load Balancers

## Public ALB

```text
Internet
   |
Public ALB
   |
Backend ASG
```

This handles:

```text
api.domain.com
```

---

## Internal ALB?

Not needed.

You mentioned:

```text
Frontend -> Internal ALB -> Backend
```

If frontend becomes S3 + CloudFront, browser traffic directly calls:

```text
https://api.domain.com
```

through the public ALB.

Much simpler.

---

# VPC Endpoint

Definitely.

Create:

```text
Gateway Endpoint
```

for:

```text
S3
```

Backend instances access S3 without internet.

---

# Bastion

For learning:

```text
Public Subnet
    |
Bastion Host
```

Fine.

For production:

I'd use:

```text
AWS Systems Manager Session Manager
```

and remove Bastion entirely.

But keeping Bastion is good Terraform practice.
